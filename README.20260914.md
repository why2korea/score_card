# why2korea_scorecard — 개인용 골프 스코어카드 웹앱

스마트폰에서 라운딩 중 한 손으로 입력하는 개인용 골프 스코어카드 기록·관리·통계 웹앱.
서버 없이 브라우저에만 저장되는 PWA(홈화면 추가 앱)이며, `../smartphone`(why2korea_memo)과
같은 방식(파일 하나짜리 vanilla JS + manifest.json + service worker + localStorage)으로 만들었다.

## (a) 2026-09-10 작업 내역 (최초 생성)

- 신규 프로젝트로 시작 (기존 README 없음).
- `../smartphone`을 분석해 기술 스택(HTML/CSS/JS 한 파일, 빌드 도구 없음), PWA 설정 방식
  (manifest.json + apple-mobile-web-app 메타태그 + service worker 캐시), localStorage 저장
  패턴(`load()`/`save()` 헬퍼 + 이름표 상수 `KEY`)을 그대로 이 프로젝트에 적용함.
  `../smartphone`의 파일은 읽기만 했고 수정하지 않음.
- 생성한 파일
  - `index.html` — 화면 1~5(메인/스코어카드/히스토리/통계/지도) 전체를 담은 단일 페이지 앱.
  - `manifest.json` — PWA 홈화면 추가 설정.
  - `sw.js` — 오프라인용 앱 셸 캐시 서비스워커(지도 타일·주소 검색은 인터넷 필요).
  - `icons/icon-192.png`, `icons/icon-512.png`, `icons/apple-touch-icon.png` — 골프 깃발 아이콘.
  - `tools/make_icons.py` — 위 아이콘을 생성하는 파이썬 스크립트(Pillow 사용, 재실행 가능).
  - `.gitignore` — 잡파일 제외 목록(이 프로젝트는 이메일 등 비밀정보를 코드에 두지 않음).
- 구현 범위: 요구사항 문서의 [화면 1]~[화면 5] 레이아웃과 기본 동작까지. 그 외 기능(삭제,
  내보내기, 다중 미완료 라운딩 선택 UI 등)은 이번 범위가 아니므로 추가하지 않음.

### 판단이 필요했던 부분과 선택 이유

- **디자인 톤**: `../smartphone`은 다크모드 기본이지만, 이 앱은 요구사항에 명시된 "야외 밝은
  햇빛 아래 가독성"을 우선해 밝은 배경 + 짙은 그린 텍스트 조합(명도 대비 최우선)을 사용함.
  PWA 구조·저장 방식만 동일하게 가져오고 색 배색은 골프 요구사항에 맞춰 새로 설계함.
- **1번 플레이어 고정**: "이**이 항상 첫 번째" 규칙을 어떤 경우에도 어긋나지 않게 하기 위해,
  1번 플레이어 이름을 "이**"으로 고정(수정/삭제 불가)하고 통계도 항상 이 선수 기준으로 계산함.
  나머지 동반자(최대 3명)는 자유 입력이며, 이름이 "유**"이면 정렬 시 자동으로 2번째로 이동함
  (안정 정렬로 나머지는 입력 순서 유지).
- **표의 "합"/"총계" 값**: Par 행은 파 합계를, 타수 행은 (Par+±)로 계산한 실제 타수 합계를,
  퍼팅 행은 퍼팅 합계를 표시함. 홀의 Par가 비어 있으면 해당 홀은 타수 합계에서 제외됨(진행 중
  라운딩에서 자연스러운 상태).
- **라운딩 완료 처리**: "미완료 라운딩"과 "히스토리"를 구분하려면 완료 상태가 필요하므로, 스코어카드
  상단에 완료/미완료 토글 버튼(✓/○)을 추가함. 요구사항에 명시되진 않았지만 두 메뉴의 동작을 위해
  꼭 필요한 최소 장치로 판단함.
- **지도**: 별도 유료 키가 필요 없는 Leaflet + OpenStreetMap 타일 + Nominatim 주소검색(모두 무료)을
  사용함. 주소→좌표 변환 결과는 `why2korea_scorecard.geocache`에 캐시해 앱을 다시 열 때마다
  재검색하지 않으며, 검색 실패 시에도 앱이 멈추지 않고 해당 골프장만 지도에서 제외됨.

## (a-2) 2026-09-10 후속 수정 (사용자 실사용 피드백 반영, 같은 날 이어서 진행)

같은 날 실제 스마트폰(안드로이드 크롬)으로 테스트하며 발견된 문제와 추가 요청을 반영함.
파일 수정 전 개별 버전 백업(`.YYYYMMDD.vN`)은 이번 세션이 계속 이어지는 한 번의 작업 흐름이라
매 수정마다 만들지 못했음 — 이 점은 프로젝트 규칙과 어긋나므로 다음 작업부터는 지킬 것.

1. **동반자 입력 구조 전면 변경**: 상단에 "동반자 최대 3명" 입력칸을 바로 노출하고, 표는
   플레이어 수와 무관하게 항상 나(이**)의 Par/score/putt 3줄만 보이도록 변경. 동반자는 이름만
   기록하고 스코어는 기록하지 않음("내 스코어만 입력하는 앱"이라는 사용자 확인에 따름).
2. **실기기 렌더링 버그 발견 및 수정**: 표를 담은 `.tablewrap`에 준 `overflow-x:auto`가 브라우저
   에서 `overflow-y`도 자동으로 `auto`가 되게 만들고, 세로 flex 레이아웃 안에서 이 요소만
   "자동 최소높이 0"으로 계산되는 CSS 규칙과 겹쳐 화면이 좁은 실기기(갤럭시 Z 폴드, 세로 814px)
   에서 표 전체가 거의 0px로 짜부러지는 버그였음. 에뮬레이터에서는 재현되지 않았고, USB로 폰을
   ADB에 연결해 Chrome 원격 디버깅으로 실제 레이아웃 수치를 확인해 원인을 특정함.
   `.tablewrap{ flex-shrink:0 }` 한 줄로 해결.
3. **레이아웃 압축** (좁은 화면에서 스크롤 최소화):
   - 일자 + 골프장 이름을 한 줄(표기 줄 + 입력 줄)로 통합
   - "나: 이**" 표시, "비워둬도 됨" 문구, "나의 총 스코어" 큰 숫자 표시 제거
   - 동반자(3칸)/캐디명(1칸) 표기를 한 줄, 입력창 4개를 한 줄로 배치
4. **표 세부 조정**: "전반 코스명"/"후반 코스명" → "전반"/"후반"(칸 폭 축소), 행 라벨
   "이**"→"score", "퍼팅"→"putt"(영문 소문자), score 기본값 E·putt 기본값 0을 미리 선택해두고
   변경 가능하게 함. `position:sticky`를 제거한 여파로 가로 스크롤 시 행 구분이 어려워진 문제를,
   "후반" 시작 지점에 Par/score/putt/Tee 라벨을 반복 표기해 해결.
5. **티샷 방향(Tee) 기록 추가**: 홀마다 티샷이 왼쪽/중앙/오른쪽 중 어디로 갔는지 기록하는 행을
   추가. 반드시 글자가 아닌 화살표 아이콘으로 선택해야 한다는 요구에 따라 select가 아닌 버튼+
   하단 시트(모달) 방식으로 구현. 왼쪽/오른쪽은 각각 일반(검정)·벌타구역(빨강)·OB(굵은 흰색
   테두리) 3가지 색으로 구분되는 화살표를 제공(중앙 포함 총 7개 아이콘).
6. **히스토리 삭제**: 각 항목에 🗑 버튼을 추가하고, 누르면 확인창(`confirm()`)을 거친 뒤에만
   삭제되도록 함.
7. **지도 기본 위치**: 처음 열 때 세계지도 대신 대한민국(제주 포함) 전체가 화면에 꽉 차게
   `fitBounds`로 맞춤. 축소하면 다른 나라도 볼 수 있음.

테스트는 실제 안드로이드 폰(USB로 PC에 연결, `adb reverse`로 로컬 서버를 폰의 `localhost:8000`
으로 터널링)에서 직접 화면을 캡처하고 탭까지 시뮬레이션해 확인함(2~5번 항목). 6~7번은 자동화된
헤드리스 브라우저 테스트로만 확인함.

### 판단이 필요했던 부분과 선택 이유 (2026-09-14)

- **8/9번 항목 위치**: 지시서는 "히스토리 — 최고/최저 스코어", "히스토리 — 버디 이상 기록"이라고
  적었지만, 실제 앱에서 최고/최저 스코어와 버디/이글 집계 카드는 히스토리가 아니라 **통계** 화면에
  있음(히스토리는 목록+삭제만 담당). 그래서 두 기능 모두 통계 화면에 구현함.
- **동반자 정렬 규칙**: 이 앱은 이전 세션 결정에 따라 "내 스코어만 기록, 동반자는 이름만"
  구조라서 별도의 "선수 순서"가 없음. 대신 "유**이 있으면 항상 두 번째" 규칙을 동반자 이름을
  화면에 표시하는 모든 곳(읽기전용 팝업, 버디 목록, 엑셀 내보내기)에서 유**을 맨 앞으로 정렬해
  적용함(`sortedCompanions()`). 입력창(동반자1/2/3) 자체의 순서는 사용자가 입력한 그대로 유지.
- **미완료 저장의 "스코어 1개 이상" 판단**: 스코어 select는 항상 기본값 0(파)이 채워져 있어
  "입력했는지 여부"를 값만으로 구분할 수 없음. Par를 하나라도 입력했는지를 "스코어 입력함"의
  대리 지표로 사용함(Par를 넣지 않으면 그 홀의 타수는 어차피 합계에도 반영되지 않는 기존 로직과
  일관됨).
- **6홀 표시 폭**: 정확한 홀 개수를 화면 크기별로 계산하지 않고, 라벨열 60px + 홀당 54px 기준으로
  약 380px 폭(일반적인 스마트폰 세로 폭)에서 6홀이 들어오도록 크기를 잡음. 기기 폭에 따라
  ±1홀 정도 차이날 수 있음.
- **종료 버튼 동작**: PWA/브라우저 탭은 스크립트가 직접 연 창이 아니면 `window.close()`가 항상
  성공한다는 보장이 없음. 실패해도 사용자가 알 수 있도록 실패 시 안내 토스트를 보여주는 방식으로
  처리(정확한 종료 성공 여부는 코드에서 감지 불가 — 실기기에서 직접 확인 필요, 아래 "확인 필요"
  참고).
- **엑셀 "플레이어별 타수"**: 이 앱은 이** 1인의 스코어만 기록하므로, 스코어 시트는 "타수(이**)"
  한 컬럼으로 단순화함(동반자는 스코어를 기록하지 않는 기존 설계와 일관).
